# Focus Lab 검증 체크리스트

## 기능 검증 범위

- A~D의 방문 압박 순서·HF/EF 순서와 10회 점프, MRF-3 2세트, 집중도 4세트, 평가압박 2회.
- 참여자 등록, 중복 코드 방지, 동의·대상 기준 체크, 연습/실제 데이터 분리.
- 참여자 화면: 한 문항씩 진행, 초기 미응답, 되돌아가기, 제출 버튼 활성화 조건, 중단 후 미제출 응답 처리.
- 기록 입력: 소수 1자리 cm, 0 및 범위 밖 값 거부, 파울/결측 사유, 유효 기록만 요약.
- 휴식 타이머 시작·정지·재개와 조기 진행 사유, 방문 간격 조기 재개 사유.
- 모든 단계 완료, 최고·평균·차이 검산, 중단 참여자 원자료 보존.
- JSON 백업 다운로드·새 탭 복원, 중복 병합 금지, 손상 JSON 거부.
- CSV 출력 종류, 연습 데이터 기본 제외, 수식 인젝션 방어.
- Sheets 설정 형식 검사, 오류/확인 상태, 수신 확인 전 성공 표시 금지, 재전송 중복 방어.

## 화면 검증 범위

- 데스크톱 1440px, 태블릿 1024px 및 768px, 모바일 375px.
- 초기 화면, 등록 모달, MRF-3, VAS, 기록 입력, 데이터, 프로토콜, 설정.
- 밝은·어두운 테마, 키보드 초점, 선택·미선택·오류·빈 상태.
- 수평 넘침과 겹침 없음. 원자료 표는 의도된 내부 가로 스크롤.

## 실연동 검증 제한

Google Apps Script는 사용자가 자신의 시트에 배포하기 전이므로 실제 Google 저장은 검증할 수 없습니다. 로컬 mock 및 정적 검증은 실제 배포 권한·CORS·Google 할당량 검증을 대체하지 않습니다. 실제 수집 전에 식별정보 없는 시험 참여자로 수신 테스트 후 시험 행을 별도 보관하세요.

## 제작 시 검증 결과

2026-09-08 기준입니다. 시험에 사용한 값은 합성 연습 자료이며 저장소에 참가자 백업·스크린샷을 포함하지 않았습니다.

- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 통과.
- `npm test`: 프로토콜·내보내기·수집기 모의 시험 24개 통과. 실제 Google API 시험은 아님.
- Chromium에서 A군 두 방문을 실제 버튼·입력으로 끝까지 진행: 준비, 사전 2회, MRF-3 2세트, 조건별 2회, 집중도 4세트, 압박 2회, 종료 확인.
- 0cm 입력 거부, 파울 사유 필수, 미응답 제출 차단, MRF 이전 응답 유지, VAS 0점과 숫자 입력 확인.
- 휴식 시작·정지·재개 및 조기 진행 사유, 48시간 이전 방문의 사유 필수 확인.
- 합성 고압박 HF 최고 251.5cm, EF 최고 249.0cm에서 차이 2.5cm 확인. 무효 시행은 유효 개수·평균에서 제외.
- 완료 JSON 다운로드·새 탭 복원 성공, 중복 병합·손상 JSON 거부, 원자료 CSV 다운로드 성공.
- 브라우저 통신을 로컬에서 가로챈 mock으로 불일치 ACK를 성공 처리하지 않음 확인. 동일 submissionId 재전송 후 일치 ACK만 저장 확인으로 표시. 데모 미전송 확인.
- 주요 5개 화면의 1440·768·375px 폭에서 페이지 전체 수평 넘침 없음. 1024×768 MRF, 375×812 MRF·VAS, 밝은/어두운 첫 화면 확인.
- 검사한 실험 흐름에서 브라우저 실행 오류 없음. 화면의 원자료 표는 좁은 화면에서 의도적으로 내부 가로 스크롤 사용.
- [실제 GitHub Pages](https://ckmzx.github.io/focus-jump-lab/)에서 HTTP 200, 정상 자산 로딩과 참가자 등록 확인. D군 연습 참여자로 중복 등록 거부, 설문 취소 후 동일 단계 유지·미제출 응답 초기화, 사유 필수 결측 처리, 중단 사유·확인 체크 필수, 중단 후 원자료 보존을 추가 검증.
- 중단 JSON에서 MRF-3 세 점수 모두 `null`이고 결측 사유와 기존 5개 단계가 보존됨을 확인. [최초 GitHub Actions 빌드·배포](https://github.com/ckmzx/focus-jump-lab/actions/runs/34179273165) 성공.

실제 iPad Safari와 Android Chrome, 실제 Google 계정·시트·Apps Script 배포는 연구 현장에서 별도로 점검해야 합니다. 조기 진행을 사용한 개발 시험은 10분·48시간 실시간 대기를 시험한 것이 아닙니다.
