# Focus Jump Lab 측정 가이드

**프로토콜:** `HF-EF-v2-web-draft-1`  
**문항 버전:** `ko-ppt-draft-1`  
문항·자극 문구·배정 순서의 실행 기준: [`src/protocol.ts`](../src/protocol.ts). 데이터 구조: [`shared/schema.ts`](../shared/schema.ts).

## 1. 적용 전 확인

이 앱은 로컬로 제공된 연구계획 PPT를 바탕으로 한 연구용 기록 도구입니다. 아래 한국어 설문은 **웹 구현을 위한 초안**으로, 검증된 한국어 번역·타당화 척도라고 주장하지 않습니다. 원본의 `폭팔` 표기는 표준 표기 `폭발`로 정규화했습니다. 실제 연구에 사용하기 전 문항, 양극단 표현, 지시 전달 방법, 결측 처리와 분석계획을 검토·확정하세요.

연구용 참여자 코드, A–D 군, 연구자 코드와 기록 메모를 사용합니다. 이름·연락처·나이·성별 등 추가 인구통계 입력란은 없습니다. 적격성·동의·프로토콜 검토 체크는 연구 기록이며, 승인된 설명문·서면 또는 전자 동의 절차를 대신하지 않습니다. 실제 참여자의 신원을 메모나 사유에 쓰지 마세요.

장비·측정 단위·기준선·착지 판정·안전 담당·중단 기준을 사전에 표준화하고, 연구자별로 같은 방식으로 운영하세요. 본 앱이 신체적 수행 가능성이나 부상 위험을 판정하지는 않습니다.

## 2. 실험 순서와 A–D 군

각 참여자는 사전 무지시 2회와 조건별 2회씩 8회를 합해 **총 10회 점프**합니다. 무지시 사전기록은 최초에만 수행하며 데이터에서 `visit = 0`으로 구분합니다. 본 실험은 2개 방문이며 각 방문에 2개 주의초점 블록이 있습니다. 실행 순서는 [`buildSteps`](../src/protocol.ts)가 고정합니다.

| 군 | 1차 방문 | 2차 방문 |
|---|---|---|
| A | 저압박 HF → EF | 고압박 EF → HF |
| B | 저압박 EF → HF | 고압박 HF → EF |
| C | 고압박 HF → EF | 저압박 EF → HF |
| D | 고압박 EF → HF | 저압박 HF → EF |

배정군은 사전 계획에 따라 연구자가 선택합니다. 앱에서 선택했다는 사실만으로 무작위 배정·배정 은폐가 성립하지 않습니다. 위 순서는 [`GROUPS`](../src/protocol.ts)와 동일합니다.

### 최초 준비

1. 승인된 적격성·동의 절차를 마친 뒤 체크리스트를 기록합니다.
2. 워밍업·지시 이해를 확인합니다.
3. 무지시 사전기록 1회·2회를 기록합니다.

### 각 방문

1. 해당 압박조건을 안내합니다.
2. 수행 전 MRF-3의 세 항목을 각각 응답합니다.
3. 첫 번째 주의초점 지시·공통 루틴을 제시하고 2회 점프를 기록합니다.
4. 방금 두 점프의 주의초점 집중도 2문항을 응답합니다.
5. **블록 사이 10분 휴식**을 확보합니다. 단순 화면 전환이나 탭의 경과시간만으로 실제 휴식 준수를 판단하지 마세요.
6. 두 번째 주의초점 블록에서 지시·2회 점프·집중도 2문항을 반복합니다.
7. 방문의 평가압박 지각 1문항을 응답하고 방문 종료를 기록합니다.
8. **JSON 백업을 다운로드한 뒤** 종료합니다.

방문 종료 확인 자체도 새로운 응답입니다. 화면의 종료 확인 버튼을 누른 뒤 최종 JSON을 한 번 더 내려받으세요. 아직 제출하지 않은 설문·저장 전 거리 입력은 백업에 들어가지 않습니다. 저장 동작은 [`App.tsx`](../src/App.tsx)를 기준으로 합니다.

2차 방문 전 **최소 48시간 간격**을 확인하고, 직전 JSON을 수동으로 가져와 같은 참여자에서 재개합니다. 시간 변경·절차 이탈이 있다면 승인된 기준에 따라 처리하고 비식별 사유를 기록하세요. 단계 순서는 [`buildSteps`](../src/protocol.ts)를 따르며 실제 경과시간과 절차 준수 확인은 연구자의 책임입니다.

고압박의 평가·비교·보상 안내는 승인된 연구계획에 맞춰 일관되게 시행합니다. **보상이 IRB/기관 계획에 승인된 경우에만** 그 조건을 설명하며, 앱이 금전·상품·성적 혜택을 자동 약속하지 않습니다.

## 3. 주의초점 자극 문구

아래 문구는 [`CUES`](../src/protocol.ts)와 일치합니다.

| 조건 | 제시 지시 | 짧은 큐 |
|---|---|---|
| HF · 전체적 주의초점 | 점프 전 과정을 하나의 빠르고 폭발적인 흐름으로 느끼며 뛰세요. | 폭발적으로 |
| EF · 외적 주의초점 | 앞쪽의 주황색 콘 방향으로 최대한 멀리 나아가는 효과에 집중하며 뛰세요. | 콘 쪽을 향해 |

큐를 전달하는 시점·횟수와 공통 루틴을 통일하고 임의로 한 조건에만 추가 코칭을 제공하지 마세요.

## 4. 설문 문항·점수 방향

### 수행 전 MRF-3 — 항목별 1–11 정수

정확한 문구와 범위는 [`MRF_QUESTIONS`](../src/protocol.ts)를 따릅니다.

| 저장 키 | 질문 | 1점 | 11점 | 높은 값의 의미 |
|---|---|---|---|---|
| `cognitive_anxiety` | 지금 마음의 상태는 어떻습니까? | 평온함 | 걱정됨 | 더 큰 인지적 불안 |
| `somatic_anxiety` | 지금 몸의 상태는 어떻습니까? | 이완됨 | 긴장됨 | 더 큰 신체적 불안 |
| `self_confidence` | 지금 점프를 수행하는 데 얼마나 자신이 있습니까? | 두려움 / 자신 없음 | 자신 있음 | **더 높은 자신감** |

**`self_confidence`는 높은 점수가 높은 자신감입니다.** 불안 항목들과 방향이 다르다는 이유만으로 자동 역채점하지 않습니다. 기본 출력은 세 항목을 따로 보존하며 합계·평균 총점·역채점 점수를 만들지 않습니다.

### 주의초점 집중도 — 블록 직후, 각 0–100 정수

양 끝은 `0 = 전혀 집중하지 않음`, `100 = 완전히 집중함`이며, 웹 입력 해상도는 1점입니다. 물리적 선 길이를 측정하는 종이 VAS와 동일한 측정 특성이 검증되었다고 가정하지 마세요. 문항은 [`focusQuestions`](../src/protocol.ts)를 따릅니다.

| 저장 키 | 조건 | 질문 |
|---|---|---|
| `focus_adherence` | HF | 방금 두 번의 점프에서 움직임 전체의 흐름과 느낌에 얼마나 집중했습니까? |
| `focus_adherence` | EF | 방금 두 번의 점프에서 목표물과 그 방향으로 나아가는 움직임의 효과에 얼마나 집중했습니까? |
| `internal_focus` | 공통 | 방금 두 번의 점프에서 신체 부위의 움직임에 얼마나 집중했습니까? |

`focus_adherence`는 해당 조건의 지시 준수 집중도, `internal_focus`는 신체 부위 움직임에 대한 집중도입니다. 두 문항은 별도 변수로 보존하며 합산·반대 방향 변환을 하지 않습니다.

### 평가압박 지각 — 방문 직후, 1–7 정수

[`PRESSURE_QUESTION`](../src/protocol.ts)의 문구는 **“방금 수행에서 나는 평가받고 있다는 압박을 강하게 느꼈다.”**입니다. `evaluation_pressure`에 저장하며, `1 = 전혀 그렇지 않다`, `7 = 매우 그렇다`입니다. 높은 값은 더 큰 평가압박 지각입니다.

### 설문 결측

미응답을 0점·중간값으로 임의 대체하지 마세요. 결측 항목은 JSON에서 `null`, 시트의 해당 점수 셀에서는 빈칸으로 보존하고 응답의 `missingReason` / 시트의 `missing_reason`에 비어 있지 않은 사유를 기록합니다. 특히 0–100 문항의 **0점은 유효 응답**으로, 결측과 다릅니다. 서버 검증 기준은 [`Code.gs`](../apps-script/Code.gs)입니다.

## 5. 점프 거리·무효·결측

단위는 **cm**입니다. 유효 기록은 유한한 숫자이며 `0 < distance ≤ 500` 범위여야 합니다. 이 범위는 입력 오류 방지용 기술 제한이지 수행 가능 범위에 관한 연구 근거가 아닙니다. 소수 기록이 가능하며 실제 측정 정밀도를 넘는 숫자를 만들지 마세요.

| `validity` | 거리 | 사유 | 요약 반영 |
|---|---|---|---|
| `valid` | 양수 cm, 최대 500 | 문자열; 필요 시 메모 | 최댓값·평균·유효 시행 수에 포함 |
| `foul` | JSON `null` / 시트 빈칸 | 필수 | 제외하되 시행 행 보존 |
| `missing` | JSON `null` / 시트 빈칸 | 필수 | 제외하되 시행 행 보존 |

사유는 예를 들어 “발 구름선 침범”, “안전상 시행 중단”, “측정 누락”처럼 비식별 내용으로 기록합니다. 무효 시행을 0cm로 바꾸거나 유효 시행으로 고치지 마세요. 기본 프로토콜은 정해진 10개 시행 위치를 기록하며 무효를 보충하는 추가 시행을 자동 생성하지 않습니다. 검증·요약 구현은 [`protocol.ts`](../src/protocol.ts)와 [`Code.gs`](../apps-script/Code.gs)에 있습니다.

## 6. 요약값과 분석의 경계

다섯 조건 `baseline`, `lowHF`, `lowEF`, `highHF`, `highEF` 각각에서 **유효 시행만**으로 최댓값, 산술평균, `valid_n`을 계산합니다. 평균은 소수 둘째 자리로 반올림하고, `recorded_n`은 무효·결측을 포함한 기록된 시행 수입니다. 유효 시행이 없으면 최댓값·평균은 빈칸이며 `valid_n = 0`입니다. 아직 시행 전인 조건과 시행했지만 모두 무효인 조건은 `recorded_n`으로 구분합니다. 구현 기준은 [`summarize`](../src/protocol.ts)와 [`Conditions` 수집 로직](../apps-script/Code.gs)입니다.

`high_difference_cm = 고압박 HF 최댓값 − 고압박 EF 최댓값`입니다. 양수는 해당 참여자의 고압박 HF 최댓값이 더 컸다는 뜻이며, 어느 쪽이든 유효 기록이 없으면 차이도 빈칸입니다. 개인별 차이·최댓값만으로 **비열등성, 우월성, 인과효과 또는 통계적 유의성**을 판단하지 않습니다.

집단 수준 비열등성 분석에는 사전에 정한 비열등성 한계, 표본수·검정력, 분석 대상 집단, 결측·무효 처리와 신뢰구간 등 별도의 분석계획이 필요합니다. 앱은 자동 비열등성 판정이나 통계적 검정을 제공하지 않습니다.

## 7. 시간과 추적 범위

응답의 `startedAt`, `completedAt`은 UTC ISO 8601 문자열이며 시트에서는 `started_at_utc`, `ended_at_utc`입니다. 화면 표시의 현지시간과 혼동하지 마세요. 참여자 행의 시작·종료는 첫 번째/마지막 **기록된 응답**의 시각이며, `status`를 함께 보아야 전체 완료 여부를 알 수 있습니다. `step_index`는 0부터 시작하고 참여자 행에서는 다음 진행 위치, 응답 행에서는 해당 단계 위치를 뜻합니다. 기준은 [공유 스키마](../shared/schema.ts)와 [수집기](../apps-script/Code.gs)입니다.

응답 기록은 단계 완료 시점의 결과 스냅샷입니다. 클릭마다의 원시 이벤트, 응답 선택 변경 과정, 재시도 요청 전체나 수정 이력을 재구성하는 감사 로그가 아닙니다. 이미 전송한 단계의 내용이 달라지면 수집기는 충돌로 거부합니다. 연구자료 정정·철회 처리는 별도 승인된 절차에 따라 담당자가 수행해야 합니다.

## 8. 현장 체크리스트

- [ ] 연구 승인·설명·동의와 적격성 확인을 완료했다.
- [ ] 문항 초안과 지시 문구를 연구 책임자가 검토했다.
- [ ] 비식별 참여자 코드와 배정군을 대조했다.
- [ ] 거리 단위·측정 위치·무효 기준·안전 중단 기준을 통일했다.
- [ ] 방문 내 10분 휴식과 방문 간 48시간 이상 간격을 확인했다.
- [ ] 각 문항에 직접 응답하거나 결측 사유를 남겼다.
- [ ] 무효·결측 시행을 0cm로 대체하지 않았다.
- [ ] 창 종료·새로고침 **전에** JSON 백업을 내려받아 확인했다.
- [ ] 다음 방문 또는 다른 기기에서는 동일 백업을 수동 가져오기 한다.
- [ ] Sheets의 `UNCONFIRMED`를 성공으로 취급하지 않고 시트를 먼저 확인했다.
- [ ] PPT·실제 결과·백업·수집 코드를 공개 저장소에 넣지 않았다.
