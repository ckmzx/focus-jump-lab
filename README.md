# Focus Jump Lab

전체적 주의초점(HF)·외적 주의초점(EF)과 압박조건을 비교하는 **연구자 진행용 제자리멀리뛰기 기록 앱**입니다. 한국어 문항은 연구계획 PPT를 웹 입력으로 옮긴 초안이며, 검증된 한국어 번역 척도나 임상 평가도구로 제공하지 않습니다. 문항·조건·순서의 기준은 [`src/protocol.ts`](src/protocol.ts), 데이터 형식은 [`shared/schema.ts`](shared/schema.ts)입니다.

## 가장 중요한 저장 안내

**창을 닫거나 새로고침하기 전에 반드시 JSON 백업을 내려받으세요.**

- 참여자·응답·입력 중인 자료는 **현재 탭의 메모리에서만** 관리합니다. `localStorage`, `sessionStorage`, `IndexedDB`를 이용한 로컬 영구저장은 사용하지 않습니다.
- 새로고침, 창 닫기, 브라우저 종료·비정상 종료 시 백업하지 않은 자료를 잃을 수 있습니다. 브라우저의 종료 경고에 의존하지 마세요.
- 방문 종료뿐 아니라 중요 입력 후에도 JSON을 내보내고, 파일이 실제로 다운로드되었는지 확인하세요. 내려받은 파일은 사용자가 관리하는 별도의 연구자료입니다.
- 재개할 때는 같은 버전의 앱에서 **JSON을 수동 가져오기** 합니다. 다른 기기로 옮길 때도 승인된 비공개 경로로 파일을 전달한 뒤 가져와야 합니다.
- 자동 기기 간 동기화, 계정 로그인, Google Sheets에서 앱으로 불러오기는 없습니다. Sheets 전송을 완료해도 앱 복구용 JSON을 대신하지 않습니다.
- JSON은 이어하기용 원본입니다. CSV 등 분석용 표는 앱 복구 파일이 아닙니다. 엔드포인트 주소와 수집 코드는 실행 시 별도 입력하고 새 탭에서 다시 설정합니다.
- 아직 제출하지 않은 설문·저장 전 거리·입력 중인 확인값은 JSON 백업에 포함되지 않습니다. 해당 단계를 저장·제출한 뒤 백업하고, 방문 종료 확인 버튼을 누른 뒤에는 최종 백업을 한 번 더 받으세요.

## 사용 흐름

1. 먼저 데모로 화면·기록·백업을 확인합니다. **데모는 Google Sheets 수집기가 거부**하며 실제 연구자료와 섞지 않습니다.
2. 실제 연구 시작 전, 연구자가 문항 초안과 프로토콜을 검토하고 적격성·동의 확인 체크리스트를 기록합니다. 이 체크리스트는 법적·기관 승인 동의서를 대체하지 않습니다.
3. 이름 대신 연구용 참여자 코드와 연구자 코드를 사용하고 A–D 배정군을 사전 계획에 따라 선택합니다. 이름·연락처·나이·성별 등 추가 인구통계 항목은 제공하지 않습니다. 메모에도 식별정보를 적지 마세요.
4. 앱의 단계 순서대로 사전기록 2회, 두 방문의 조건별 점프 8회와 설문을 기록합니다. 조건 간 10분 휴식, 방문 간 최소 48시간을 연구자가 확인합니다.
5. 매 방문 종료 전 JSON 백업을 다운로드합니다. 다음 방문은 해당 백업을 가져와 **동일한 참여자 ID**로 이어갑니다.
6. 선택적으로 Sheets에 전송합니다. 일치하는 수신 확인이 있을 때만 전송 확인으로 취급하고, `UNCONFIRMED`이면 시트를 확인한 뒤 같은 ID로 재시도합니다.

정확한 A–D 순서, 문항, 점수 방향과 기록 원칙은 [측정 가이드](docs/MEASUREMENT_GUIDE.md)를 따르세요.

## Google Sheets 연동 — 코드·설치 안내만 제공

현재 저장소는 Google 계정에 연결하거나 실제 시트를 생성하지 않습니다. 연구자가 비공개 시트에 [`apps-script/Code.gs`](apps-script/Code.gs)를 설치·배포하고, 실행 중인 앱에 배포 주소와 수집 코드를 직접 입력하는 방식입니다. [단계별 설치·시험·오류 대응](apps-script/README.md)을 먼저 읽으세요.

수집기는 참여자별 요약, 응답별 긴 형식 표, 시행별 거리, 조건별 파생 요약을 기록합니다. 같은 참여자·단계 키의 동일 재시도는 중복 행을 만들지 않으며, 이미 수집된 응답의 다른 값으로 덮어쓰기는 거부합니다. 읽기·자료 다운로드 API와 원시 클릭 이벤트 감사 로그는 제공하지 않습니다.

**`no-cors`로 바꾸어 성공처럼 표시하면 안 됩니다.** 전송은 `text/plain` JSON, `mode: 'cors'`, `redirect: 'follow'`를 사용하며, 읽을 수 있는 JSON 응답의 `ok === true`와 요청에 일치하는 `submissionId`가 필요합니다. 브라우저·기관 계정 정책에 따라 응답 확인이 차단될 수 있으므로 실제 사용할 브라우저에서 더미 자료로 검증해야 합니다. Content Service의 리디렉션 동작은 [Google 공식 안내](https://developers.google.com/apps-script/guides/content)에 설명되어 있습니다.

## 공개 저장소와 개인정보 경계

- 예정 공개 소스: `ckmzx/focus-jump-lab`
- GitHub Pages 주소 형식: `https://ckmzx.github.io/focus-jump-lab/` — 실제 공개 여부는 저장소의 Pages 배포 결과에서 확인하세요.
- **공개 대상은 앱 소스·문서·합성 테스트뿐입니다.** 연구계획 PPT 원본, 실제 결과, JSON 백업, CSV, 시트 사본, 참여자 식별표, 스크린샷 속 실제 자료, 수집 코드·자격증명은 업로드하지 마세요.
- 원본 PPT는 로컬 제공 자료로 검토되며 저장소나 빌드에 포함하지 않습니다. GitHub Issues·Actions 로그에도 실제 자료를 붙여넣지 마세요.
- Sheets 문서는 비공개로 두고 연구팀에만 최소 권한을 부여합니다. 웹 앱의 호출 가능 범위와 시트 자체의 공유 범위는 별개입니다.
- 시트는 연구자가 통제하는 수집 사본입니다. 보존·백업·접근권한·철회 후 처리·삭제 정책은 연구 승인 절차에 따라 별도로 정해야 합니다.

## 로컬 개발

Node.js 22 이상을 권장합니다.

```sh
git clone https://github.com/ckmzx/focus-jump-lab.git
cd focus-jump-lab
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

`npm test`에는 Node VM으로 Google 서비스를 모의하는 Apps Script 테스트가 포함됩니다. 이것은 실제 Google 배포, OAuth·조직 정책, 브라우저 CORS 성공을 보증하는 통합 시험이 아닙니다.

## GitHub Pages 배포

1. `ckmzx/focus-jump-lab`에 **소스 파일만** 푸시합니다. 푸시 전 `git diff --cached --name-only`로 PPT·백업·결과·비밀값 포함 여부를 확인하세요.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. 저장소의 `.github/workflows/` Pages 워크플로가 테스트·빌드 후 `dist`만 배포하는지 확인합니다. 기본 브랜치 푸시 또는 제공되는 수동 실행으로 배포합니다.
4. Actions가 성공한 뒤 Pages 배포 주소를 엽니다. [`vite.config.ts`](vite.config.ts)는 상대 경로 `base: './'`를 사용해 `/focus-jump-lab/` 하위 배포에서도 자산을 불러옵니다. 이를 변경한다면 배포 경로와 맞추세요.
5. 실제 브라우저에서 데모 입력 → JSON 내보내기 → 새로고침 → 수동 가져오기를 확인합니다. Sheets를 사용할 경우 별도 테스트 시트에서 수신 확인도 검사합니다.

Apps Script는 Pages와 **별도로** 배포합니다. Apps Script 코드를 고쳤다면 새 버전을 웹 앱 배포에 반영해야 합니다. Google의 배포·실행 주체·`/dev` 시험 주소 설명은 [Web Apps 공식 문서](https://developers.google.com/apps-script/guides/web)를 참조하세요.

## 설계상 한계

- 점수 합산·자신감 역채점은 기본으로 수행하지 않습니다. 고압박 HF–EF 거리차는 기술통계이며, 개인 1명의 차이로 비열등성·효과·통계적 유의성을 판정하지 않습니다.
- 한국어 문구와 시행 규칙의 확정, 안전관리, 표본수·비열등성 한계·분석계획 사전 결정은 연구자의 책임입니다.
- 고압박 조건의 보상·순위·비교 안내는 승인된 IRB/기관 계획에 한해서만 적용하며 앱이 보상을 자동 약속하지 않습니다.
- 수집 코드는 간단한 공유 비밀값이지 개인별 인증이나 고보안 연구 데이터 플랫폼을 대체하지 않습니다. 민감정보 수집, 대규모 운영, 정교한 감사 추적이 필요하면 별도 승인된 시스템을 사용하세요.
